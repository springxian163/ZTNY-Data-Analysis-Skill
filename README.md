# ZTNY Data Analysis Skill

把 SAP 导出的《验收单报表》变成一套可直接上会的分析材料：**Excel 分析看板 + Word 分析报告**。

适用于内蒙古仲泰能源集团（ZTNY）的采购验收数据月度/季度/年度复盘，也可用于任何字段结构相同的 SAP 验收单报表。

> **核心设计：结论由规则引擎生成，不是模型自由发挥。**
> 同一份数据跑两次，输出的每一个数字、每一句判断逐字节一致。月度报告之间因此可以横向对比、可以审计追溯。

## 为什么不是「让 AI 写一份报告」

一次性让大模型读数据写报告，三个问题绕不开：

| 问题 | 后果 |
|------|------|
| 同一份数据两次结论不同 | 月度报告无法横向对比，说不清「上个月和这个月到底哪变了」 |
| 数字靠模型复述 | 偶发编造、单位错位、四舍五入失真（7.61 亿写成 8 亿） |
| 口径不固定 | 这个月按全年比、下个月按同期比，同比数字失去意义 |

本项目把流程拆成 **数据 → 指标 → 阈值判定 → 模板化措辞** 四段，模型只负责调用，不参与计算与判断：

```
验收单报表*.xlsx
      │  loader.py      流式解析 XML（SAP 导出的 xlsx 用 openpyxl 读会卡死）
      ▼
  DataFrame（清洗、日期还原、字段标准化）
      │  analyzer.py    自动削平可比区间 → 十维指标
      ▼
  analysis_result.json（全量结构化结果）
      │  rules.py       阈值判定 → findings / problems / actions
      ▼
  ┌───────────────┴────────────────┐
  excel_writer.py             md_writer.py → html_writer.py → docx
  11 工作表看板                 九章 Word 报告
```

## 快速开始

### 环境要求

- Python 3.10+
- 依赖见 `requirements.txt`（pandas / openpyxl / python-docx）

```bash
pip install -r requirements.txt
```

### 运行

```bash
# 方式一：手动指定文件（文件说清了路径时用这个）
python scripts/run.py \
  --files "D:/data/验收单报表2025.xlsx" "D:/data/验收单报表2026.xlsx" \
  --out   "D:/data/分析输出" \
  --org   "内蒙古仲泰能源集团"

# 方式二：自动扫描目录（只说「分析这个月的数据」时用这个）
python scripts/run.py \
  --dir "D:/仲泰/仲泰2026/10月/数据分析" \
  --out "D:/仲泰/仲泰2026/10月/数据分析/分析输出" \
  --org "内蒙古仲泰能源集团"
```

### 参数

| 参数 | 必填 | 说明 |
|------|------|------|
| `--files` | 二选一 | 报表路径，空格分隔多个 |
| `--dir` | 二选一 | 递归扫描该目录下的 `验收单报表*.xlsx` |
| `--out` | ✅ | 输出目录，不存在会自动创建 |
| `--org` | 建议 | 单位名称，用于封面与标题 |
| `--title` | 否 | 覆盖默认报告标题 |
| `--skip-excel` | 否 | 只出 Word |
| `--skip-docx` | 否 | 只出 Excel + JSON |
| `--keep-html` | 否 | 保留 `stage1/` `stage2/` 中间产物，便于排查排版 |

**文件命名要求**：文件名必须含 4 位年份（`验收单报表2025.xlsx`）。脚本按年份分组，同一年有多份时取最后修改的那份。

耗时参考：9.9 万行双年数据约 **90 秒**（读数据 60s + 分析 10s + 文档生成 20s）。

## 分析模型：十个维度

| # | 维度 | 关键指标 |
|---|------|---------|
| 1 | 总量与增速 | 验收金额、笔数、平均单笔、同比、全年外推 |
| 2 | 月度节奏 | 逐月金额/笔数、峰谷月、累计进度 |
| 3 | 物资结构 | 五大类占比与同比、消耗性 vs 资本性拆分 |
| 4 | 供应商集中度 | CR1/CR5/CR10/CR20、活跃家数、新增/退出、细分品类 CR3 |
| 5 | 交付时效 | 逾期率、平均逾期天数、逾期深度分布、逾期供应商榜 |
| 6 | 价格异动 | 可比物料涨跌中位数、涨幅/降幅榜、同规格多供应商价差 |
| 7 | 矿点分布 | 各使用单位金额、同比、变动贡献 |
| 8 | 长尾小额 | 小额订单笔数与金额占比、流程负担评估 |
| 9 | 协议类型 | 合同/协议/无依据采购的结构 |
| 10 | 数据治理 | 空值率、日期异常、使用单位缺失的金额影响 |

指标的精确定义与计算公式见 [`references/metrics.md`](references/metrics.md)。

## 口径约定

这几条是报告可信度的基础，改动前请先读完。

### 1. 同比区间自动削平

数据往往是不完整的年份。例如 2026 年数据只导到 10 月 1 日，直接和 2025 年全年比会严重低估。

`analyzer.determine_compare_months()`：

1. 取最新年份的实际数据截止月；
2. 若该月金额占本年比重 < 2%（例如只有 1 天的数据），**回退一个月**；
3. 与基期可覆盖月份取交集，得到 `months`。

实际案例：2026 年数据到 10/1，10 月仅 130 万元（占比 0.17%）→ 剔除 → 可比区间 **1—9 月**。

### 2. 逾期要看两个数

- `逾期天数 > 0` 即逾期；`< -3000` 的极端值视为脏数据剔除。
- **逾期率**看逾期面，**平均逾期天数 / 60 天以上占比**看逾期深度。
- 逾期率平稳但平均天数大涨，说明逾期正从偶发变为常态——这是比逾期率更重要的信号，报告会单独提示。

### 3. 价格可比性门槛

只有同时满足以下条件的物料才进比价：

- 两年均有采购记录；
- 各自年度采购数量 ≥ 10。

不满足的多为单次采购噪声，纳入会污染结论。

### 4. 同规格价差

按 `(物料描述, 供应商名称)` 聚合均价，要求：每供应商数量 ≥ 20、该描述下 ≥ 2 家、`最高价/最低价 ≥ 1.5`。

能识别「同规格不同供应商报价悬殊」，**不能**识别「同物异码」（同一物资录成多个物料描述），后者需人工梳理主数据。

### 5. 降价榜为什么设 5% 门槛

单价同比 -0.1% 属于正常议价波动。若按「所有下降」排序，榜单会被柴油、锚杆这类超大金额、微幅波动的品种占满，看不到真正值得复盘的案例。设 ≥5% 门槛后，榜单才有可比性。

### 6. 使用单位缺失

「使用单位」为空通常是设备类资产直供（库存地 = 设备直供库），不是录入错误。报告同时给出**全量占比**与**可比区间占比**，避免读者对不上账。

### 7. 榜单统一按金额排序

所有 TOP 榜（供应商、涨幅、降幅）按**本期金额**排序而非幅度，让金额影响优先于极端值。

### 8. 退出 ≠ 终止合作

`04B` 的退出名单只表示本期无可比区间的验收记录，长周期设备供应商可能因当期无需求而自然缺席。停供天数以**本期数据截止日**为基准（不是 today），保证反复运行结果一致。

## 结论阈值

所有判定阈值集中在 `scripts/rules.py` 的 `THRESHOLDS`，改这里即可调整灵敏度：

```python
THRESHOLDS = {
    "concentration_drop_good": 3.0,    # CR5 下降 > 3pp → 结构改善
    "concentration_high": 30.0,        # 单品类 TOP1 占比 > 30% → 依赖风险
    "overdue_worsen_days": 3.0,        # 平均逾期恶化 > 3 天 → 严重
    "overdue_severe": 10.0,            # 60天以上占比 > 10% → 严重
    "price_gap_alert": 2.0,            # 同规格价差 > 2 倍 → 异常
    "hot_growth": 50.0,                # 品类金额增幅 > 50% → 异动
    "small_order_share": 40.0,         # 小额订单笔数占比 > 40% → 流程负担
    "yoy_flat": 1.5,                   # |同比| < 1.5% → 基本持平
    "yoy_slight": 5.0,                 # 1.5% ≤ |同比| < 5% → 小幅波动
}
```

每条 `finding` 含 `level`（danger/warn/good/info）、`title`、`facts[]`、`implication`，Word 与 Excel 的结论章节都直接引用它，保证两处口径一致。阈值调整方法与反模式见 [`references/thresholds.md`](references/thresholds.md)。

### docx 生成的两条路径

| 引擎 | 触发条件 | 说明 |
|------|---------|------|
| `html-to-docx` | 检测到 WorkBuddy tencent-docx 插件 | 排版最精细，优先使用 |
| `builtin` | 插件不可用 | `docx_fallback.py`，纯 python-docx 实现，A4/宋体五号/1.5 倍行距/页脚页码 |

强制使用内置引擎：`export HTML2DOCX_PY=/nonexistent`。也支持用该环境变量指向其他 `html_to_docx` 环境。

## 常见问题

**报错「缺少必需字段」**
报表模板变了或导出漏列。脚本会打印缺失字段与实际字段，对照 `loader.REQUIRED_COLS` 补映射即可。

**报错「需要至少两年数据才能做同比」**
`--files` / `--dir` 只找到一年数据。补上基期年份，或加 `--skip-docx` 只出 Excel。

**xlsx 打不开 / 读出来只有一行**
SAP 导出的 xlsx 结构特殊：openpyxl 普通模式会卡死、只读模式 `max_row` 恒为 1。本项目已改用 `zipfile` 直接解析 `xl/worksheets/sheet1.xml`，10 万行约 10 秒。若你自己写脚本，注意表头是 HTML 实体（`&#20844;&#21496;` = 公司），需要 `html.unescape()`。

**docx 里目录变成 1./2./3. 自动编号**
`<ol class="toc-list">` 会被某些转换器渲染成 List Number。本项目已改用 `<div>` + `<p class="toc-item">`。

**想改报告风格**
`html_writer._TEMPLATE` 是完整 CSS，色板走 `--color-*` 变量，优先读 `stage2/design_tokens.json`，缺省用 `DEFAULT_TOKENS`。

**输出 xlsx 报 PermissionError**
文件正被 Excel / WPS 打开。关闭后用 `--out` 换目录重跑。

## 数据与隐私

本仓库**不含任何业务数据**。`.gitignore` 已排除 `*.xlsx`、`*.docx`、`analysis_result.json`、`stage1/`、`stage2/`，避免误提交验收单或分析结果。
