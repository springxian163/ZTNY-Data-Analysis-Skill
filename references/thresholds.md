# 阈值调整指南

`rules.THRESHOLDS` 决定"什么情况算问题"。默认值基于内蒙古仲泰能源集团的
2025—2026 双年数据标定，换企业或换行业时需要重新校准。

---

## 默认值与含义

```python
THRESHOLDS = {
    "concentration_drop_good": 3.0,    # pp
    "concentration_high": 30.0,        # %
    "overdue_worsen_days": 3.0,        # 天
    "overdue_severe": 10.0,            # %
    "price_gap_alert": 2.0,            # 倍
    "hot_growth": 50.0,                # %
    "small_order_share": 40.0,         # %
    "yoy_flat": 1.5,                   # %
    "yoy_slight": 5.0,                 # %
}
```

| 键 | 触发条件 | 触发的结论 |
|----|---------|-----------|
| `concentration_drop_good` | `CR5` 下降 ≥ 该值 | 供应商格局 → `good`（结构改善） |
| `concentration_high` | 单品类 TOP1 占比 > 该值 | 供应商格局 → 追加"依赖"提示 + 生成问题项 |
| `overdue_worsen_days` | 平均逾期天数同比增加 > 该值 | 交付时效 → `danger` + 生成问题项 |
| `overdue_severe` | 60 天以上占比 > 该值 | 交付时效 → `danger` |
| `price_gap_alert` | 最大同规格价差 ≥ 该值 | 价格与成本 → `danger` + 生成问题项 |
| `hot_growth` | 品类金额增幅 > 该值 | 标记为异动（`hot_keywords`） |
| `small_order_share` | 小额订单笔数占比 > 该值 | 长尾与小额 → `warn` + 生成问题项 |
| `yoy_flat` | 金额同比绝对值 < 该值 | 趋势判为"基本持平" |
| `yoy_slight` | 金额同比绝对值 < 该值 | 趋势判为"小幅增长/下降" |

---

## 怎么校准

### 方法一：看历史分布，取分位数

对每个阈值，先统计历史多期的实际分布，取"明显偏离常态"的分位点。

例如 `overdue_worsen_days`：
```
2023→2024: +1.2 天
2024→2025: +0.8 天
2025→2026: +13.3 天   ← 显著异常
```
常态波动在 ±2 天以内，阈值设 3.0 合理；若某企业常态波动 ±5 天，应上调到 6—8。

### 方法二：按管理层容忍度定

阈值本质是"什么程度值得上会"。可与管理层确认：
- 逾期率上升多少个点要专项汇报？
- 价差多少倍算不合理采购？
- 供应商集中度降到多少算分散到位？

把答案直接换算成阈值，比统计方法更有管理意义。

### 方法三：按行业基准

| 行业 | `concentration_high` 建议 | 理由 |
|------|--------------------------|------|
| 煤炭/矿业 | 30%—35% | 设备主机厂天然垄断，集中度高有合理性 |
| 制造业通用件 | 15%—20% | 替代性强，高集中度不合理 |
| 化工原料 | 25%—30% | 受资源禀赋约束 |

## 调整后的验证

改完阈值一定要用**历史数据回测**：

```bash
# 用去年的数据跑，看新阈值下结论是否符合实际认知
python run.py --files 验收单报表2024.xlsx 验收单报表2025.xlsx \
  --out ./backtest --skip-docx
```

检查 `analysis_result.json` 的 `conclusions`：
- `problems` 数量是否合理（一般 3—6 个，太少说明阈值太松，太多说明太紧）；
- `alert_count`（danger 级别数）应为 0—2 个，超过 3 个会让报告失去重点。

## 反模式（不要这么做）

**❌ 为了让报告"好看"而调阈值**
阈值是分析工具，不是化妆工具。如果数据显示确实恶化，就该报出来。

**❌ 每个指标都设成敏感**
全部触发 = 全部不触发。报告的重点在于区分"必须处理"和"需要关注"，
`danger` 只应留给真正紧急的问题。

**❌ 只改阈值不改措辞模板**
阈值变了，`rules.py` 里对应的 `implication` 文案也要跟着调，
否则会出现"触发的是危险级，说的却是平稳"的错位。

---

## 措辞模板的位置

结论文案分散在 `rules.build()` 各段，按主题排列：

| 主题 | 位置 | 可变部分 |
|------|------|---------|
| 总体规模 | `_implication_total()` | 按 yoy 分四档 |
| 物资结构 | `build()` 第 2 段 | 结构分化时用专门文案 |
| 供应商格局 | `build()` 第 3 段 | 按 delta 分三档 |
| 交付时效 | `build()` 第 4 段 | danger/warn/good 三档 |
| 价格 | `build()` 第 5 段 | 按中位变化 + 价差倍数 |
| 长尾 | `build()` 第 6 段 | 固定文案 |
| 数据治理 | `build()` 第 7 段 | 固定文案 |

修改文案时保持"结论 + 依据 + 建议"三段结构，不要只给判断不给依据。
